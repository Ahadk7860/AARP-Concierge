# Shared Contracts — Boi

**Frozen as of:** the foundation commit on `main`.
**Owner of changes:** the user. No agent modifies this file unilaterally.

## How to use this file

You are one of four agents working on this project in parallel, in separate git
worktrees. You cannot see the other tracks' code and you must not depend on reading
it. Everything you need from them is specified here, literally.

Code against these definitions exactly as written. If your implementation needs
something this file does not specify, that is a **contract gap**: stop, commit your
work in progress, write the gap into your track's `NOTES.md`, and report it to the
user. Do not invent the missing piece and do not edit this file.

Section 11 lists what is deliberately **UNRESOLVED**, almost all of it downstream of
not having a Linq token yet. Read it before you assume something is missing by
accident.

## 0. What Boi is, in one paragraph

A consumer AI assistant that lives in iMessage. A companion Mac app reads the user's
local iMessage history, so Boi is the only assistant that knows their *relationships* —
who they're close to, who they're losing, who is waiting on a reply right now. Each
morning it texts a brief of at most three people, and for each one it drafts **two**
candidate messages in the user's own voice. It never sends them; the user does.

Three properties everything else depends on:

- **The corpus never moves.** 84,000 messages stay on the Mac. Only abstractions cross
  the boundary. Local SQL over the whole corpus takes under two seconds, so there is no
  upload, no progress bar, and no drop-off window.
- **The Mac is allowed to be asleep.** Staleness is a visible state, never a silent
  wrong answer.
- **Delivery does not depend on the Mac.** The cloud sends the morning text.

### The three shapes worth reading in full before you start

**`voice_pack.v1`** carries the user's **own sent messages**. It is the reason drafting
does not break the digest boundary: the voice we imitate is the user's, the content we
must understand is somebody else's, and those separate. Section 7 covers the guards.

**`gist.v1.facts`** is an allowlist, not decoration. It is the complete set of
specifics a draft is permitted to name. Anything outside it — a date, a time, a place,
an amount, a person — is an invented commitment sent in the user's own name.

**`draft_bundle.v1.candidates`** is **exactly two, or exactly zero.** Never one, never
three. The two must differ in **stance** (`answer` vs `defer`), not in phrasing — two
paraphrases of the same sentence is a fake choice and users notice immediately. Zero is
a legitimate degraded outcome when the validator refuses both after one retry. A brief
with no draft is fine. A brief with a bad draft is a trust event.

## 2. API surface

Full spec: `contracts/openapi/boi-api.v1.yaml`. Produced by **Track D**, consumed by
Track A (uploads) and Track C (webhook delivery).

| Endpoint | Purpose | Notable response |
|---|---|---|
| `POST /v1/digest` | upload a T0 digest | `202` · `409 {"error":"duplicate"}` on a repeated `generated_at` |
| `POST /v1/voice-pack` | upload one voice pack | `202` · **`422 {"error":"redaction_failed"}`** — pack rejected and NOT stored |
| `POST /v1/heartbeat` | Mac liveness | `204` |
| `POST /v1/pair` | six-digit code → device token + `user_salt` | `200` · `404 {"error":"invalid_code"}` |
| `DELETE /v1/users/{id}` | delete everything, derived data included | `204` |
| `POST /v1/webhooks/{provider}` | inbound from transport | `204` · `401 {"error":"bad_signature"}` |

Shared error bodies, every endpoint:

```json
{ "error": "validation", "detail": "string" }
{ "error": "unauthorized" }
```

### The Linq subset

`contracts/openapi/linq-v3-subset.yaml`, implemented by Track C's mock server. **The
spec is reconstructed from published docs and has never been run against a live
account.** Recorded transcripts are in `contracts/transcripts/linq/`.

```
POST https://api.linqapp.com/api/partner/v3/chats
Authorization: Bearer <token>
{ "from": "+1...", "to": ["+1..."], "message": { "parts": [...], "protocol": "auto" } }
→ 200 { "id", "status", "protocol", "trace_id" }
→ 429 Retry-After
→ 503 { "error": "line_banned" | "line_degraded" | "upstream", "line_id" }
```

## 3. Data schema

Owner: **Track D**. Migrations live at `cloud/db/migrations/` and only Track D writes
them.

Two properties are load-bearing and cannot be retrofitted once there is data:

```sql
-- Every table carries user_id and is partitioned on it, so delete is ONE operation
-- that covers derived data. CCPA is not optional, and one-click delete that leaves
-- derived rows behind is exactly the gap the FTC prosecutes.
create table users (
  user_id      text primary key,
  phone_e164   text not null unique,
  email        text,
  user_salt    bytea not null,     -- issued once at pairing, never rotated
  timezone     text not null default 'America/Los_Angeles',
  created_at   timestamptz not null default now()
);

-- contact_id = HMAC(user_salt, normalized_handle), computed ON THE MAC.
-- The same phone number produces a DIFFERENT id for every user, so cross-user joins
-- are arithmetically unavailable -- not "forbidden by policy" but unavailable to a
-- rogue query or a subpoena. This is the shadow-profile line rendered in schema.
-- The server NEVER sees a raw handle for anyone but the account holder.
create table relationships (
  user_id      text not null references users(user_id) on delete cascade,
  contact_id   text not null,
  display      text not null,
  payload      jsonb not null,     -- conforms to digest.v1 $defs/relationship
  as_of        timestamptz not null,
  primary key (user_id, contact_id)
) partition by hash (user_id);
```

**Never join users to each other.** If two users both text the same person, those rows
must not link. Crossing that line is what ended NGL.

## 6. Shared conventions

- **Times** are ISO 8601 UTC strings with a `Z`, at every boundary. No epoch integers
  cross a process line.
- **`as_of` on every fact, end to end** — digest, storage, prompt, tool result. It must
  be structurally impossible to lose, because the failure mode is Boi confidently
  saying something false about a person's friend.
- **IDs**: `usr_` users, `dev_` devices, `h_` contacts (HMAC hex), `g_` gists, `vp_`
  voice-pack versions, `omsg_`/`lmsg_` messages.
- **Naming**: `snake_case` in JSON, SQL, and Python; `camelCase` inside TypeScript
  code but `snake_case` on every wire shape; Swift properties match the JSON keys
  exactly so `Codable` needs no `CodingKeys`.
- **Errors**: `{ "error": "<slug>", "detail"?: string }`. Slugs are lowercase snake.
- **Logging**: structured JSON to stdout. **Log the prompt hash, never the prompt.** A
  bad draft must be reproducible from `(voice_pack_version, gist_id, prompt_version,
  model_id)` without a prompt log full of user content sitting in an observability
  vendor.
- **Tests** live beside the code (`*.test.ts`, `intelligence/tests/`,
  `mac/Tests/`).

### Product conventions that are not style preferences

- **Invitation, never verdict.** `"you've reached out to Sarah 12 times this month"`,
  never `"Sarah doesn't text you back"`. Every reveal ships with a one-tap remedy.
  Guilt without agency is repellent; guilt with a button is a product.
- **Never auto-send.** Ever. The approval tap costs nothing and buys everything.
- **Don't ship reciprocity.** Across 25 real relationships the spread was 0.465–0.615,
  sd 0.034 — it carries almost no information, and it is the most legally dangerous
  metric in the category. Momentum (0.0×–13.9×) is where the signal is.
- **Degrade, never fabricate.** No drafts beats bad drafts. A vague gist beats a
  hallucinated one. "Haven't seen your Mac since Sunday" beats a confident wrong
  answer.

| `LINQ_WEBHOOK_SECRET` | Track C generates for dev | `.env` | Track C | `dev-secret-change-me` |
| `device_token` | issued by `POST /v1/pair` | macOS Keychain (Track A) | Track A | any string against the stub |
| `user_salt` | issued by `POST /v1/pair` | macOS Keychain (Track A) | Track A | any 32 bytes |

### `is_from_me = 1`, guarded three times

Voice-pack exemplars must originate from message rows the **user wrote**. This is
asserted in three independent places, and all three ship:

1. **The SQL query** on the Mac (Track A) and in the reference builder (Track B).
2. **The upload boundary** — `POST /v1/voice-pack` returns `422 redaction_failed` and
   stores nothing (Track D).
3. **A test that fails the build** — `scripts/check_voice_pack_leak.py` (Tracks A and B
   both run it).

One inbound message riding along in an exemplar list makes every privacy claim in the
architecture false, and nobody would notice for months. **This is a frozen anchor. Do
not weaken any of the three to make a checklist green.**

Redaction, applied on the Mac before an exemplar is ever serialized: phone numbers,
email addresses, street addresses, dollar amounts, and third-party full names. A
redacted exemplar is just as good a style sample and carries none of the risk.

**The rule:** a track may **append** — add a dependency, add a variable, add a file
reference. It may not reorder, reformat, remove from, or restructure. Every append is
recorded in that track's `NOTES.md` under `## Shared file changes`. Never hand-edit a
lockfile; regenerate it with the project's tool. Conflicts there are expected at merge
and the user resolves them.

The baseline dependencies for all four tracks are already in `package.json` and
`pyproject.toml`, deliberately, so appends should be rare.

paths still destroy each other if they contend for the same port, database, or key.

|---|---|---|---|---|
| Port range | 3010–3019 (unused) | 3020–3029 | **3030–3039** | **3040–3049** |

| Scratch / output | `/tmp/boi-a` | `/tmp/boi-b` | `/tmp/boi-c` | `/tmp/boi-d` |

| Container prefix | — | — | `boi-c-` | `boi-d-` |

### Rate-limited APIs and live calls

| API | Live calls permitted | Which track | Otherwise |
|---|---|---|---|
| Gemini | **yes** | **Track B only** | `FakeProvider` replaying `contracts/transcripts/model/` |
| Kimi / OpenRouter | no — key not provisioned | — | `FakeProvider` |
| Linq | **no — no token exists** | — | Track C's mock at `localhost:3031` |
| Apple / iCloud | n/a | — | — |

Even Track B: **the default test path is `FakeProvider`.** Live calls require both

harness, not the unit suite. Three agents on one key hit the limit at a third of the
throughput each, and the failures read as flaky tests.

Anything not listed here is unassigned. A track that needs an unlisted resource records
it in `NOTES.md` under `## Runtime resources` and reports, rather than picking a
default another track may also pick.

## 10. Stub and fixture location

Everything below landed in the foundation commit on `main`, **before any worktree was
created.** It is therefore already on your branch — you never need to reach into
another track's worktree, and you must not try.

| Stub | Path | Returns |
|---|---|---|

| Synthetic `chat.db` | `scripts/make_synthetic_chatdb.py` | real schema, NULL-text rows, tapbacks, a group chat, **an open WAL** |

### Language-neutral artifacts

Required because tracks span Swift, Python, and TypeScript: a Swift client cannot
execute a Python mock, and a track that cannot run the stub has no verifiable
Definition of Done.

| Artifact | Path | Use |
|---|---|---|
| JSON Schemas | `contracts/schema/*.json` | the arbiter for every shape |
| Validator | `scripts/validate_fixtures.py` | check any document from any language |
| Static fixtures | `contracts/fixtures/**` | plain JSON on disk, readable from anywhere |
| Linq transcripts | `contracts/transcripts/linq/*.json` | request/response pairs, including `503 line_banned` |
| Model transcripts | `contracts/transcripts/model/*.json` | replayable model output, including two deliberate violations |
| API specs | `contracts/openapi/*.yaml` | generate a client, validate shapes |

**Every consuming track must be able to reach a green Definition of Done without
running another track's code.** If that stops being true, it is a contract gap.

### The one thing the fixtures cannot give you

`scripts/make_synthetic_chatdb.py` cannot produce real `attributedBody` **typedstream**
blobs. Apple's typedstream is an undocumented pre-plist `NSArchiver` format, and a
hand-rolled fake would let a broken decoder pass — which is the worst possible outcome,
because getting this wrong silently loses roughly **47% of the corpus** and reads as
"the report is thin" rather than as a bug.

So the decoder is verified against the developer's **own** `chat.db`, read-only, with a
metric rather than a fixture: the share of messages with no recoverable text must fall
from ~47% to under 2%. That check runs locally and commits nothing. See Track A prompt
`03`.

The fixture database does give you the **WAL** property, which is the other silent
killer:

```
mode=ro      -> 9637 rows
immutable=1  -> 9636 rows     # ignores the WAL, freezes the corpus, raises no error
```

## 11. UNRESOLVED

Almost all of this is downstream of not having a Linq token. Tracks consuming an
unresolved contract code against the placeholder and flag the dependency in `NOTES.md`.

| # | Item | Placeholder | Owned by | Resolve by |

| 6 | Are we notified **before** a number rotates? | assume no | user | before signing |

| 9 | Does the three-click grant survive macOS 26 (Tahoe)? | MVP ships **Full Disk Access**, which works everywhere | user | before launch, not before merge |

choosing a model. Build the eval harness, run them through it, move on.
